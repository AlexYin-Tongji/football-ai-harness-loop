# 球脉（FootPulse AI）产品需求文档

- 状态：Draft v0.1
- 日期：2026-06-28
- 负责人：Product
- 目标交付：世界杯淘汰赛期间的可用 MVP

## 1. 一句话产品

球脉是一款面向中文足球用户和内容创作者的 AI 报告工作台：用户选择主题后，系统调用大模型 API，把实时资料整理为可追溯、可编辑、可导出的报告；最终内容由用户整理并发布到自己的社媒。

## 2. 用户问题

用户不是缺足球消息，而是缺少：

- 低噪声：同一条消息被数十个账号重复转述。
- 可判断：传闻、接触、报价、达成协议和官宣混在一起。
- 可追溯：AI 摘要经常丢失原始出处和时间。
- 可解释：预测只给一个比分，没有概率、版本与历史表现。
- 中国时区友好：赛程、日报和提醒未按北京时间组织。

## 3. 目标用户与任务

### 3.1 核心用户

1. 需要快速选题、核验来源并组织社媒内容的足球创作者。
2. 希望直接获得一份完整足球报告的中文球迷。
3. 喜欢赛前分析、但不满足于无依据“拍脑袋预测”的数据型球迷。

### 3.2 用户任务

- “早上让我在 5 分钟内知道过去 24 小时真正重要的转会进展。”
- “开赛前让我看懂双方状态、关键缺阵和概率变化。”
- “每天用一篇中文文章回顾世界杯，并知道今天值得看什么。”
- “给我一份结构清晰的报告，我再按自己的风格改成微博、公众号或视频脚本。”

## 4. 产品范围

### 4.1 P0：世界杯期间必须上线

- 报告工作台：选择报告类型、日期/比赛、长度与写作侧重点。
- 世界杯日报报告：昨日赛果、关键事件、晋级形势、今日赛程、关注点。
- 赛前预测报告：胜/平/负研判、可能比分、晋级倾向、依据与风险。
- 每条事实可展开查看来源、发布时间和核验状态。
- 报告历史、重新生成、局部改写、复制 Markdown/纯文本与导出 JSON。

### 4.2 P1：世界杯期间补齐

- 每日转会简报。
- 关注球队、球员与订阅提醒。
- 预测变化曲线与模型历史成绩页。
- 用户风格预设和社媒格式参考，但仍由用户确认并手动发布。

### 4.3 暂不做

- 不做实时文字直播；数据延迟与版权成本不适合 MVP。
- 不提供投注建议、赔率比较或“稳胆”。
- 不连接或自动发布到微博、微信、小红书、抖音等社媒。
- 不把模型报告标记为已经过用户审核的最终稿。
- 不在 MVP 阶段拆成大量微服务或放任智能体无限循环。

## 5. 信息架构

```text
报告工作台
├── 新建报告
│   ├── 每日转会报告
│   ├── 世界杯日报
│   └── 比赛预测报告
├── 今日推荐主题
├── 生成进度与校验结果
└── 报告历史

资料库
├── 来源与主张
├── 世界杯赛程/赛果
└── 球队/球员事件时间线

设置
├── 报告长度与风格
├── 模型与成本偏好
└── 导出偏好
```

## 6. 核心体验

### 6.1 每日转会消息

系统将文章拆成“主张（claim）”，围绕球员、来源俱乐部、目标俱乐部、动作、金额、阶段和时间建立事件簇，而不是简单拼接标题。

阶段统一为：

`传闻 → 关注/接触 → 谈判 → 报价 → 达成协议 → 体检/签约 → 官宣`

同时允许 `停滞`、`告吹`、`辟谣`。每个卡片展示：

- 一句话进展与“相比昨日发生了什么”。
- 当前阶段、置信等级、首次/最近更新时间。
- 支持来源与冲突来源。
- AI 整理标识，不展示伪造引语。

进入报告正文的门槛：

- A（确认）：官方来源，或权威来源且有独立佐证。
- B（可信进展）：至少两个独立可靠来源，关键信息一致。
- C（单一消息）：可以进入“传闻观察”，不可写成确定事实。
- D（噪声/冲突）：不进日报正文，仅留审计记录。

### 6.2 世界杯日报

固定结构让用户形成习惯：

1. 30 秒摘要。
2. 昨日赛果与关键转折。
3. 晋级/对阵变化。
4. 伤停与球队消息（标注来源和时间）。
5. 今日北京时间赛程与三场看点。
6. AI 研判：明确标为模型推断，并列出依据、反例和不确定性。
7. 更正记录与完整来源。

日报中的赛果、赛程、排名必须来自结构化赛事数据源，生成模型不得自行计算或凭记忆补全。

### 6.3 比赛预测

默认报告包含：

- 90 分钟胜/平/负的 AI 概率判断，三者之和为 100%。
- 最可能的比分区间与淘汰赛晋级倾向，明确区分常规时间、加时和点球。
- 支持与反对该判断的关键因素、数据截止时间、模型名称和提示词版本。
- 历史命中与 Brier Score；样本不足时明确写明“尚未校准”。

不展示“必然比分”。MVP 直接调用 DeepSeek V4 API，不训练自有大模型；系统记录预测和赛果，用真实表现决定未来是否增加轻量统计基线。

## 7. 功能需求与验收

| ID | 需求 | MVP 验收标准 |
|---|---|---|
| NEWS-01 | 多源采集 | 支持 API、RSS 和许可网页适配器；原始记录不可覆盖 |
| NEWS-02 | 去重聚类 | 同一主张跨来源合并，保留所有出处 |
| NEWS-03 | 证据核验 | 每个事实句至少关联一个证据片段和 URL |
| NEWS-04 | 内容生成 | 模板化初稿；无证据字段保持空缺而非补写 |
| REPORT-01 | 报告生成 | 支持三类报告、生成进度、失败重试和版本历史 |
| REPORT-02 | 用户整理 | 支持局部改写、复制 Markdown/纯文本和导出 JSON |
| REPORT-03 | 发布边界 | 不存储社媒凭据，不自动对外发布 |
| WC-01 | 世界杯日报 | 每日北京时间 08:00 前可生成带来源报告 |
| PRED-01 | 赛前预测 | 开赛前 24h/6h/75min 可重算并保留版本 |
| PRED-02 | 可解释性 | 展示关键输入、反方证据、数据截止和 LLM 运行版本 |
| PRED-03 | 结果评估 | 赛后回填结果并计算报告预测的 Brier Score |
| TRUST-01 | 来源透明 | 用户能从事实或预测跳转到来源/数据说明 |
| OPS-01 | 可观测性 | 每次运行可查看步骤、输入版本、输出、耗时和失败原因 |
| OPS-02 | 可降级 | LLM 不可用时返回已收集资料包和清晰失败原因 |

## 8. 信任与安全

- 内容层明确区分“事实、来源观点、模型推断、编辑观点”。
- 对伤病、纪律、合同金额等易变信息显示“截至时间”。
- 系统永不自动发布社媒；报告顶端提示用户在发布前复核。
- 更正不静默覆盖，保留版本和更正说明。
- 页面显示数据/新闻来源归属，遵循抓取许可、robots 与供应商协议。
- 预测不面向未成年人营销，不与博彩转化绑定。

## 9. 成功指标

### 北极星指标

每周完成至少 3 次“有效阅读”的用户数；有效阅读定义为阅读日报/转会简报超过 45 秒，或展开至少一个来源/预测解释。

### 质量护栏

- 报告事实的来源覆盖率：100%。
- 经确认的事实性错误率：< 1%，严重错误为 0。
- 重复消息压缩率：> 70%。
- 世界杯日报人工审稿中位耗时：< 10 分钟。
- 报告导出率、二次生成率和用户保留率。
- 预测：持续记录 Brier Score；首 30 场只展示观察值，不宣称模型已校准。

点击率、阅读时长不能压过事实准确率和校准度。

## 10. 关键产品决策

1. MVP 是报告生成工具，不是媒体发布平台。
2. 默认使用 DeepSeek V4 API：Flash 负责批量抽取/整理，Pro 负责最终综合与比赛研判。
3. 同一 Harness 运行内容与预测报告，但提示词、证据模板、校验和评估分开。
4. 用户看到的是报告、证据和不确定性；最终编辑与社媒发布由用户负责。
5. 先做响应式 Web 报告工作台；数据与留存验证后再决定原生 App。
