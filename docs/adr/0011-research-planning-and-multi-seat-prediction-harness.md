# ADR 0011：研究规划 Harness 与多席位预测汇总

- 状态：Accepted
- 日期：2026-07-02

## 背景

旧资料层以固定关键词直接读取 RSS/GDELT/NewsAPI。中文主题、宽泛主题或单一来源短暂
失败时，用户容易看到“近期资料不足或来源暂时不可用”，但系统实际上没有先规划查询、
扩大同义搜索，也没有把失败原因带入报告。

## 决策

1. 新增 `ResearchHarness`：先由轻量模型生成受治理的搜索计划，再用计划驱动已登记的
   RSS、GDELT 与 NewsAPI 连接器取数。
2. 搜索计划只生成查询词、用途和允许来源组合，不直接浏览网页，不抓取未登记站点，不
   保存完整新闻正文。
3. 当规划模型失败、返回非法 JSON 或本地 mock 模式运行时，Harness 使用确定性英文
   兜底查询，避免中文主题无英文 token 时直接失败。
4. 只找到发现层线索时允许继续生成“线索/传闻”报告，并把覆盖不足写入
   `collection_warnings`；质量门仍要求 `unverified_lead` 不能写成确认事实。
5. 预测委员会从两个席位扩展为三个席位：状态/数据席、战术席、怀疑席；最终由高阶
   模型汇总。外部平台预测只从证据中抽取和展示，不由模型补造。

## 后果

- 用户输入中文或宽泛主题时，系统会先规划多组英文检索词再查批准来源。
- 单个来源故障不再直接中止；报告会披露来源覆盖下降。
- 发现层线索可以进入传闻雷达，但不会升级为事实。
- 预测报告更接近“资料收集 + 多角度独立判断 + 高阶汇总”的流程。

## 验证

- 中文主题必须生成英文兜底查询。
- 仅有一条发现层线索时，Research Harness 应返回资料包和 warning，而不是直接抛出
  资料不足。
- 预测正常路径应使用三个分析席位加一个终审席。
- 旧质量门仍拒绝无传闻标签的发现层引用。
