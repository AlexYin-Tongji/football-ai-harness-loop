# ADR-0002：采用 API-first 报告工作台

- 状态：Accepted
- 日期：2026-06-28
- 决策来源：产品负责人反馈

## 背景

产品的真实交付物不是自动发布的新闻页面，而是一份供用户整理、改写并发布到社媒的报告。团队也不希望在 MVP 阶段训练大量模型，希望直接利用最新大模型 API。

## 决策

- 产品只生成、保存、改写和导出报告，不持有社媒凭据，不自动发布。
- 首选 DeepSeek V4：`deepseek-v4-flash` 用于高吞吐抽取、翻译和初步整理，`deepseek-v4-pro` 用于最终报告与比赛研判。
- 通过 OpenAI-compatible Provider 接口隔离供应商；模型名、超时、预算和思考模式均为配置。
- 大模型不自行浏览互联网。Harness 获取实时资料，构建带来源和截止时间的结构化上下文包。
- 比赛预测先采用 LLM judgment：要求输出 JSON、概率和正反证据，经过确定性校验后写入报告。
- 暂不训练自有模型。保存每次预测与赛果，持续测量 Brier Score；只有数据证明有价值时再增加 Elo/Poisson 等轻量基线。
- 用户修改或导出是工作流终点；社媒发布发生在系统外。

## 后果

正面：更快上线、初始工程和 ML 成本更低，报告格式容易迭代，也不会误发社媒。

代价：LLM 给出的概率不天然校准，实时信息质量取决于外部数据源；因此必须显示“AI 判断”、数据截止和历史样本，并保留更换模型或增加统计基线的空间。

## 退出条件

若连续样本显示 LLM 预测显著失准、成本不可控或输出不稳定，则引入轻量确定性基线并让 LLM 只负责解释，不直接生成概率。
