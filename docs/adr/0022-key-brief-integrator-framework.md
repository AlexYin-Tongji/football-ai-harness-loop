# ADR 0022：Key Brief 关键信息整合框架

- 状态：Accepted
- 日期：2026-07-06

## 背景

2026-07-06 的人工复测显示，Facts-first 和 gap-driven search 已经显著改善了“当天比赛清单、基础赛果、基础转会消息”的覆盖，但生成层仍有三类产品问题：

1. 模型容易把日报写成长文战报或来源复述，缺少“从大量信息里抽取关键热门信息”的取舍。
2. 分桌和最终合稿仍携带旧目标，例如配图、官方高光、完整长段落和内部 evidence 摘要，导致兜底稿偶尔出现调试痕迹。
3. 人物、教练和转会阶段等领域知识如果只靠模型临时理解，容易出现背景缺失、阶段混乱或证据外补写。

用户给出的微信文章只作为产品形态参考，不进入生产事实源；生产事实仍必须来自 Source Registry、结构化数据或批准的新闻检索/摘要能力。

## 决策

1. 保留 Facts-first 事实层：当天比赛清单、比分、开球时间和结构化缺口继续先于模型生成。
2. 日报生成层改为 Key Brief：系统不要求模型创作完整长文，而是要求每个 story 输出【核心】【细节】【背景】【下一步】【边界】短卡片。
3. 新增 `daily_briefing_playbook` 领域注入：把产品角色、转会阶段梯度、北京时间规则、点球大战规则、人物/教练背景边界和禁止可见文本统一注入 Leader、分桌和最终合稿。
4. 图像、视频、GIF 和高光自动链路暂时关闭：日报和转会报告不再规划 `media_targets`，增强层过滤 `licensed_image`、`official_video` 和 `gif` 需求，最终报告清空 `media_assets`。
5. 确定性兜底也使用 Key Brief：即使最终 LLM JSON 不稳定，兜底报告也必须输出同样的短卡片结构，并把内部 evidence 标记隔离在读者正文之外。
6. 搜索/MCP 方向采用受控缺口模式：模型可以暴露 unknowns 和 coverage gaps，但不能把对话历史、任意网页或未登记 MCP 结果当作事实库；新增搜索 MCP 前必须登记 Source Registry、设定预算、超时、重试和证据校验。

## 后果

- 输出从“创作一篇日报”变为“交付可编辑的关键信息 brief”，更接近用户想要的信息整合产品。
- 模型需要做的推理减少：转会阶段、时间窗口、点球大战、人物背景边界由 playbook 显式给出。
- 视觉体验会暂时变弱，但文本产品更稳定；后续恢复视觉功能时可单独评估许可、相关性和前端展示。
- 搜索能力继续演进，但必须通过受控连接器进入证据包，而不是让模型自由浏览后直接写事实。

## 验证

- 单元测试覆盖最终合稿 prompt 注入 `daily_briefing_playbook`，且不再包含旧的 180-420 字长段落要求。
- 单元测试覆盖 deterministic daily finalizer 输出【核心】和【边界】短卡片，并隐藏内部 evidence 标记。
- 单元测试覆盖增强层过滤图片、视频和 GIF 需求。
- 端到端测试继续覆盖结构化比赛清单、转会栏目覆盖、claim 修复和 reader-safe fallback。
