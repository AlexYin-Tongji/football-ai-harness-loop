# ADR 0013：来源 Playbook 与编辑型四层 Agent 刷新

- 状态：Accepted
- 日期：2026-07-03

## 背景

多轮真实测试暴露出三个问题：资料覆盖不稳定、关键人物/比赛信息增强不足、最终文案过度强调可靠性而缺少足球报告的阅读感。旧版四层流水线已经拆开 URL 收集、资料精简、增强和撰写，但“去哪些站点找”“精简成什么格式”“何时回溯原链接”“怎样写得像报告”仍散落在提示词和代码里。

## 决策

新增两个横向 Skill：

1. `source-discovery`：给 URL 收集层提供足球来源 Playbook。它列出官方、英文主流、西语、意语、法德和结构化候选来源，并规定只能在 Source Registry / Publisher Registry 已登记的边界内使用 RSS、GDELT、NewsAPI 等发现工具。
2. `evidence-refinement`：给资料精简层定义短证据包格式。每条摘要必须绑定原 `source_evidence_id`，保留原链接、发布时间、来源状态、关键数字和传闻标签。

更新 `research-enhancement`：明确球员、俱乐部、赛事和关键画面分别去哪里补。许可图片继续走 Commons；官方视频继续走白名单；GIF、新闻配图、社媒截图和比赛片段没有批准自动来源时，只生成具体人工补图任务。

更新写作层提示：最终报告要像足球编辑给读者的报告，先讲变化、背景和意义，再说明证据边界。传闻、冲突和未知项仍必须显式存在，但不把正文写成可信度审计清单。

扩展 Publisher Registry：增加常见官方俱乐部/联赛域名，以及 Marca、AS、Diario Sport、Mundo Deportivo、L'Equipe、Gazzetta、Kicker 等批准发现发布者。新增域名只允许元数据发现和引用回溯，不新增全文抓取器。

## 不变边界

- 未登记来源不能进入生产稿件。
- 不保存完整新闻正文、付费原文、社媒截图、比赛片段或隐藏推理。
- GDELT/NewsAPI 结果默认是发现线索，不自动成为事实证据。
- Transfermarkt 仍在未取得书面授权前禁用。
- 比赛结果写入、报告导出和模型配置变更仍走显式权限检查。

## 后果

- 资料收集更可解释：Trace 能看出来源规划、精简、增强和写作分别采用哪个 Skill。
- 精简层输入给撰写层的内容更小，但仍能通过原链接回溯。
- 增强层不再只依赖 YouTube；它会优先补结构化资料和许可图，并对关键比赛画面生成可执行人工清单。
- 最终文案减少重复风险声明，改为“报道 + 证据边界”的结构。

## 验证

- 测试需要覆盖新增批准发布者域名能被 GDELT/NewsAPI 元数据解析接受。
- 测试需要覆盖精简层 prompt 包含 `original_url` 和 `evidence-refinement` Skill。
- 测试需要覆盖 GIF/关键画面需求变成 warning，而不是媒体资产。
