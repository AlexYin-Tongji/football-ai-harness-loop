# 《今日球脉》日报写法基准

- 状态：Draft
- 日期：2026-07-04

## 参考观察

公开足球日报和战报常见结构可以分成两类：

1. 战报型：先交代北京时间、赛事、场地、对阵和最终比分；随后按“关键事件”列出进球、VAR、点球、红牌、比分变化和晋级影响。懂球帝战报页通常采用这种信息密度高的结构，适合赛场主线。
2. Daily briefing 型：先给当天最重要的主线，再把比赛、转会、场外和背景串成一篇有判断的日报。Guardian Football Daily/Football 频道更接近这种“主线 + 语境 + 补充线索”的组织方式。

这些参考只用于产品结构和信息组织，不复制原文表达，也不把未授权页面正文存入系统。

## 球脉目标版式

1. **开场 30 秒**：用 3-5 句讲“今天真正变化了什么”，并明确哪些是确认事实、哪些是报道线索。
2. **关键信息卡**：每个二级标题使用【核心】【细节】【背景】【下一步】【边界】组织；没有证据支持的标签可以省略，但不能用空话填充。
3. **赛场主线**：每场比赛独立成段。先写北京时间/赛事/对阵/比分，再写证据支持的进球、VAR、红牌、点球或晋级影响；结构化源没有 events 时只写赛果和影响。
4. **转会市场**：每个重要转会独立成段，按传闻、接触、报价、谈判、原则协议、体检、官宣或辟谣标注阶段；金额、合同、体检时间没有证据就不写数字。
5. **人物/教练补充**：只在能帮助理解主线时出现。身份、位置、现俱乐部、履历节点、成绩和赛季数据必须来自证据或授权结构化来源。
6. **来源边界**：正文自然写出来源名和不确定性，来源链接由 UI 列表和 evidence tag 承担；不要把文章写成审计清单，也不要暴露内部 evidence 调试文本。
7. **视觉素材暂缓**：图片、视频、GIF、高光和截图不进入当前自动链路；后续重新接入时必须走 Source Registry 和单独质量门。

## 质量门映射

- 每个二级标题至少绑定一个 `evidence_id`。
- 每个带数字的 claim 必须能在引用证据中找到同一数字。
- `unverified_lead` 相关 claim 必须逐句保留“传闻/据报道/未核实/线索”标签。
- 战报栏目若存在多场比赛，必须拆成多个二级标题。
- 转会栏目若存在多条转会，必须拆成多个二级标题。
- 当前版本不生成媒体资产；任何自动图片/视频能力恢复前必须新增 ADR 并补回许可、相关性和展示质量门。
