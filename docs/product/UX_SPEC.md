# MVP 体验与页面规格

## 1. 设计方向

界面像一个清醒、克制的足球报告工作台，而不是信息流、CMS 或博彩盘口。深色比赛模式与浅色阅读模式均可用；颜色不单独承担“可信/不可信”含义，所有状态同时使用文字和图标。

## 2. 报告工作台

```text
┌──────────────────────────────────────────┐
│ 球脉     新建报告  报告历史  资料库  设置 │
├──────────────────────────────────────────┤
│ 今天想生成什么报告？                     │
│ 世界杯日报 / 比赛预测 / 每日转会          │
├──────────────────────┬───────────────────┤
│ 今日比赛              │ 推荐报告主题     │
│ 时间 / 对阵 / 生成    │ 资料覆盖 + 生成  │
├──────────────────────┴───────────────────┤
│ 最近报告：状态 / 模型 / 截止时间 / 导出   │
└──────────────────────────────────────────┘
```

- 所有时间默认北京时间，并允许切换本地时区。
- 首屏先帮助用户创建报告，不提供站内媒体信息流。
- 每个报告显示生成进度、数据截止、模型与质量警告。

### 2.1 新建报告

用户只需选择报告类型和主题；高级选项折叠：

- 报告日期或具体比赛。
- 篇幅：精简 / 标准 / 深度。
- 侧重点：新闻脉络 / 数据 / 战术 / 社媒选题。
- 模型：自动（推荐）/ V4-Flash / V4-Pro。
- 输出：Markdown / 纯文本 / JSON。

生成过程显示“收集资料、核验来源、生成提纲、撰写报告、质量检查”，允许取消。

## 3. 世界杯日报页

- 顶部：日期、生成/更新时间、模型、复制和导出。
- 30 秒摘要：最多 5 条，每条可展开来源。
- 昨日比赛：比分、关键事件、晋级影响。
- 今日比赛：北京时间、场地、预测入口。
- 报告正文：事实句末使用来源序号；悬停/点击打开来源抽屉。
- 底部：方法说明、警告、完整来源、重新生成和局部改写。

移动端使用单列；赛果和今日比赛支持横向紧凑卡片，但正文不横向滚动。

## 4. 比赛详情与预测

预测报告信息顺序：

1. 比赛状态、开球时间、球队、场地。
2. 90 分钟概率条：胜/平/负同时显示数值。
3. 淘汰赛晋级概率（若适用），与 90 分钟卡视觉分隔。
4. 期望进球与最可能比分，不高亮成“推荐比分”。
5. 已验证的关键因素和缺失数据提示。
6. 版本历史、更新时间、模型/提示词和当前样本表现。
7. 复制 Markdown、复制纯文本、下载 JSON；没有“一键发布社媒”。

状态：

- `scheduled`：展示 T-24h 或最新预测。
- `lineup-pending`：提示首发后还会更新。
- `final-prediction`：首发版，开赛后冻结。
- `live`：仅显示赛前预测存档，不把它更新为实时预测。
- `finished`：预测与赛果并列，计入模型表现。
- `data-stale`：显著展示数据截止，不悄悄沿用旧阵容信息。

## 5. 转会日报与事件卡

事件卡的主视觉是“阶段变化”，不是夸张标题：

```text
球员 A：俱乐部 X → 俱乐部 Y
[谈判中 · B 级可信]  2 小时前更新
变化：Y 已提交正式报价；金额尚无可靠来源。
支持来源 2    冲突来源 1    查看时间线
```

- 可按球队、球员、阶段、可信等级过滤。
- 默认折叠无实质变化的重复报道。
- 时间线展示首次消息、实质更新、辟谣/官宣，不展示转载洪流。

## 6. 来源抽屉

抽屉不复制全文，只展示足够判断的信息：

- 来源名称、等级、作者、发布时间和语言。
- 该来源支持/反驳了哪条主张。
- 原文链接与“为何认为是独立来源”的说明。
- AI 翻译/摘要标识、抓取时间和内容可能更新提示。

冲突来源并排展示，不让用户误以为系统已经消除争议。

## 7. 预测表现页

- 当前 LLM、提示词版本和报告样本。
- 最近 30/100 场 Log Loss、Brier 与方向准确率。
- 校准图：例如预测 60% 的事件是否约 60% 发生。
- 样本太少时明确提示“尚未校准”；未来可与透明基线对比。
- 按赛制/数据完整度分组，避免总体均值掩盖失败。

## 8. 报告详情与异常队列

```text
报告运行详情
├── 来源冲突
├── 低置信度主张
├── 引用缺失 / 数值不一致
├── 生成/复核失败
├── 用户反馈
└── 模型 API / 成本异常
```

报告页采用三栏：左侧报告结构，中间正文，右侧证据与校验。硬性校验失败时禁止导出“完整报告”，但允许用户下载资料包。用户的局部改写、重新生成和反馈会形成评估数据。

## 9. 可访问性与文案

- 正文对比度达到 WCAG AA；键盘可访问来源抽屉和概率说明。
- 概率同时提供文字，不只用颜色或面积。
- “已确认”“单一来源”“存在冲突”“模型推断”等词全站统一。
- 避免“稳赢、必进、爆冷预警”等赌博化或确定性文案。
- 所有自动生成内容提供反馈与更正入口。
- 导出前提示：“请核对事实与措辞，最终发布责任由用户承担。”
