# ADR 0010：Token 预算化模型控制与公共 API 边界

- 状态：Accepted
- 日期：2026-07-02

## 背景

《今日球脉》深度模式的最终总编辑阶段曾同时接收完整 JSON Schema、完整 Skill、
压缩证据包和分桌草稿。随着 RSS、GDELT、NewsAPI 与事件簇数量增加，最后一步容易因
上下文过大或长推理连接中断而失败。与此同时，旧的同步接口仍允许调用方直接提交
`evidence`，不适合作为公共产品入口。

## 决策

1. 增加独立的模型控制层 `model_control.py`，为不同阶段定义 thinking 开关、输出预算
   和输入字符预算。
2. 《今日球脉》最终合稿阶段不再接收完整 Skill 和完整 Pydantic Schema；只接收：
   紧凑证据索引、分桌草稿摘要、Harness 确定性合稿提纲和小型 JSON 输出契约。
3. 日报最终合稿默认关闭 thinking；分桌研究和栏目写作仍可使用 thinking。若最终阶段
   失败，稳定合稿继续使用更小的输出预算；再次失败则进入确定性保守合稿。
4. 比赛预测必须输出 `analysis_process`，说明从赛前证据、支持因素、反方因素和未知项
   如何走到概率；质量门检查这些分析步骤引用的 evidence ID。
5. 浏览器公共入口只使用 `/v1/research/jobs`。旧的 `/v1/reports/generate`、
   `/v1/runs` 和 `/v1/research/reports` 默认隐藏，只有
   `FOOTPULSE_INTERNAL_API_ENABLED=true` 时才用于内部调试和测试。
6. 赛果写入不允许重复静默覆盖。同一预测任务已有结果时，后续更正必须走显式更正工作流。

## 后果

- 深度日报最后一步的输入显著变小，失败时也更容易降级到可解释状态。
- 模型不能在最终合稿阶段重新发现事实，必须基于分桌成果和证据索引整理。
- 预测报告会更像分析，而不是只有胜平负百分比。
- 公共攻击面缩小，调用方不能绕过 Source Registry 自带来源生成生产报告。
- 后续若要开放 API 给第三方，需要单独设计带鉴权、来源注册和配额的公共接口。

## 验证

- 深度日报最终请求的 prompt 字符数应低于旧实现，并关闭 thinking。
- 旧原始 evidence 接口默认返回 404。
- 预测输出缺少 `analysis_process` 时，Harness 基于已验证证据补入保守分析骨架。
- 重复写入预测赛果必须失败并留下审计记录。
