# ADR 0017：专栏小组内循环与媒体缓存交付

- 状态：Accepted
- 日期：2026-07-03

## 背景

真实测试显示，先全局收集资料再分给小组，会造成两个问题：一是最终报告不收敛，同一主题两次生成可能漏掉不同栏目；二是媒体素材只是远程视频卡或候选链接，不能稳定放到战报和球员小节中。

用户期望的是 Leader 先决定哪些小组出动，然后每个小组自己完成收集、精简、增强、写作检查和必要迭代，最后由总编辑合稿。

## 决策

1. 日报研究流改为 `Seed URL → Seed 精简 → Leader 初始分组 → Column Team Loop → Leader 复审 → 写作交付`。
2. 每个 Column Team 内部固定四个角色：Scout、Refiner、Enhancer、Writer/Reviewer。每组最多 3 轮；连续两轮无新增证据或媒体即停止。
3. 小组循环写入独立 `column_team_loop` trace，记录小组、迭代轮数、证据数、媒体数和覆盖状态。
4. 最终合稿增加覆盖门。若 Leader 栏目未进入正文，或战报/转会没有按事件拆成二级标题，最多再生成到 3 次；仍失败则交给质量门与人工审核。
5. 媒体层可以把已批准的 Wikimedia Commons 图片和官方 YouTube 缩略图下载到本地 `artifacts/media/`，并通过 `/media/` 暴露给前端。原始 URL、许可和署名必须保留。
6. 仍禁止自动抓取新闻正文图片、社媒截图、GIF 和比赛片段；未登记来源只能作为人工补图提示。

## 后果

- 每个栏目拥有自己的搜索和增强上下文，减少全局候选池挤掉转会、球员或战报图的概率。
- 报告稳定性从“模型一次写全”改为“覆盖门推动多次合稿”，两次生成的栏目差异应收敛。
- 前端可以展示本地缓存的战报图/球员图候选，同时保留来源回溯。
- 工具轮次和模型轮次会增加，但仍受 runtime 上限、检查点和人工回退约束。

## 验证

- 测试覆盖中文关注词召回热刺/Spurs。
- 测试覆盖日报 RSS 源内读取深度。
- 测试覆盖 column team loop 出现在 Trace。
- 测试覆盖最终合稿漏掉 Leader 栏目时会自动重试。
- 测试覆盖批准图片缩略图可缓存到 `/media/`。
