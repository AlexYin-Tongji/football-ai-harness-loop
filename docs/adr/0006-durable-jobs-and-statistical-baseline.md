# ADR 0006：持久化研究任务与统计预测基线

- 状态：Accepted
- 日期：2026-07-01

## 背景

同步报告请求会让用户长时间等待，并且进程重启后丢失运行状态。比赛概率完全来自 LLM judgment，缺少可复现的对照基线与赛后评估闭环。

## 决策

1. 公共页面改用持久化研究任务：创建任务后返回不透明 UUID，前端轮询真实状态；采集、证据就绪、研究席位、总编辑、质量门和完成均来自后端事件，不再使用模拟计时器。
2. 本地 Beta 使用 SQLite WAL 保存任务、最终报告和审计事件；数据库文件被 Git 忽略。生产部署保持 PostgreSQL/Temporal 目标，不把 SQLite 当作多实例执行器。
3. 服务重启时，未完成任务被标记为 `interrupted` 并提示用户重试，不假装已恢复模型调用。
4. 比赛预测增加可复现的 Poisson 基线；当来源提供 Elo 时使用 Elo 调整 Poisson。每队少于三场结构化赛果时不生成基线，不用默认球队实力填空。
5. 统计基线由代码计算并在模型校验后注入，LLM 不得修改。Pro 输出继续作为“综合研判”，页面同时展示两者与有证据的外部预测。
6. 赛果写入必须同时通过管理令牌与 `result_writer` 角色检查；写入后计算多分类 Brier Score 和 Log Loss。

## 结果

任务和结果在本地重启后仍可查询，用户看到的进度与真实阶段一致。预测概率有了可复现参照，但只有取得批准的结构化赛果数据时才显示；没有数据时明确缺失。

## 验证

- 重建 JobStore 后能读取已完成任务。
- 未完成任务在重启后进入 `interrupted`。
- Poisson/Elo+Poisson 概率归一化且相同输入产生相同输出。
- 模型尝试自行写入统计基线时质量门拒绝。
- 没有 `result_writer` 角色不能写入赛果。
