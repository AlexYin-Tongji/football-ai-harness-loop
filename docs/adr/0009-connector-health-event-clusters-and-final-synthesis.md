# ADR 0009：连接器健康、事件簇与最终合稿提纲

- 状态：Accepted
- 日期：2026-07-02

## 背景

产品已经能生成日报、转会和预测报告，但仍有三类体验风险：

1. 外部 Key 已配置却没有可用数据，用户无法判断是套餐覆盖、权限还是系统问题。
2. 转会传闻来源变多后，单篇文章列表不足以支撑编辑判断，需要按“事件/线索”组织。
3. DeepSeek 长上下文最终合稿阶段偶发断线，单纯降级不能解释工作流层面的稳定性。
4. 许可图片可能满足版权条件，但不一定是目标球员或比赛，需要相关性筛选和人工复核。

## 决策

1. 新增后台连接器健康接口和 `/admin` 健康卡片。接口只返回配置状态、覆盖状态、错误
   类型和建议，不返回密钥、完整付费数据或新闻正文。
2. Sportmonks 健康探针按五大联赛逐项检查：Premier League、La Liga、Serie A、
   Bundesliga、Ligue 1。`not_covered` 明确表示当前 token 没有返回该联赛，不伪装
   成系统可用。
3. NewsAPI 只作为 Source Registry 批准域名上的元数据扩展层。系统仅保存标题、URL、
   发布时间和短描述；结果标记为 `unverified_lead`。
4. 新闻证据进入模型前分配 `story_cluster_id`，并在摘要中加入事件簇规模、独立来源数、
   传闻阶段关键词和同簇标题，帮助研究桌像编辑部线索池一样处理转会/赛事信息。
5. 日报最终阶段新增 Harness 确定性合稿提纲。提纲由分桌草稿和事件簇生成，不引入新
   事实，只约束栏目边界、去重、引用和传闻标签；最终编辑仍必须通过 schema 与证据校验。
6. Commons 图片进入报告前必须同时通过许可证白名单和姓名/元数据相关性筛选；无视觉
   模型时仍标记为“待人工确认”。YouTube 仍只允许人工白名单官方频道，不下载视频。
7. Google Cloud Vision 登记为可选视觉相关性供应商，优先用于低成本标签、OCR、安全
   识别和 Web 实体辅助；视觉结论不改变足球事实与版权状态。

## 后果

- 用户可以在管理台看到“已配 key 但没数据”的具体原因。
- 转会日报能保留更多传闻和绯闻，同时不把未核实线索升级为事实。
- 最终合稿输入更小、更有结构；若高思考请求失败，稳定合稿和确定性保守合稿仍保留。
- 媒体素材更安全，但没有视觉服务时仍需要人工确认画面是否正确。

## 验证

- 管理接口必须鉴权；未启用 Admin 时返回 404，令牌错误返回 403。
- Sportmonks 探针不得输出 token，只输出联赛覆盖状态和 League ID。
- NewsAPI 解析不得保存正文 `content`，所有条目标记为 discovery/unverified lead。
- 事件簇必须保留 `story_cluster_id`，并在摘要中展示独立来源和同簇线索。
- 最终合稿 prompt 必须包含 Harness 确定性合稿提纲，且仍使用压缩证据索引。
- Commons 图片缺少姓名/元数据相关性时不得进入报告。
