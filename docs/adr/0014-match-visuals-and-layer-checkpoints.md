# ADR 0014：赛事视觉首图、关键事件媒体与分层检查点

- 状态：Accepted
- 日期：2026-07-03

## 背景

用户希望世界杯日报接近成熟足球资讯产品：首屏有赛事结束后的总图，进球或 VAR 等关键事件下方有对应画面，文字按栏目合并，而不是把新闻散成短条。同时需要看到每个子模型/子 Harness 交给下一层的东西是否可靠，避免某层静默降级。

## 决策

1. 自动媒体优先使用官方可嵌入视频及其缩略图。FIFA/赛事官方或 Source Registry 登记的授权转播方 YouTube 白名单视频可作为 `report_cover`、`timeline` 或 `section` 媒体资产；系统只保存视频 URL、embed URL、缩略图、标题和频道署名，不下载或重新托管。YouTube Data API 限流或无结果时，系统可读取同一白名单频道的公开视频 feed 做元数据降级。
2. 媒体搜索改为证据驱动。增强层从具体证据标题/摘要生成“赛事首图”和“关键事件画面”目标，不再用泛化的 `World Cup highlights` 查询；媒体层只接受球队、球员、事件等字母令牌匹配，年份、比分和号码不能单独触发命中。
3. 官方视频可承担“图像”职责：前端把视频缩略图作为大首图或时间线画面展示，并标注官方视频外链。若没有官方或授权媒体命中，系统宁缺毋滥。
4. Getty Images 等世界杯授权摄影机构登记为采购/人工审核候选，不在未配置合同、许可和署名流程前自动抓图或盗链。新闻正文图片、社媒截图、动图和比赛片段仍不得自动嵌入。
5. 最终日报按栏目合并。`ReportSection` 增加可选 `category`：`match`、`transfer`、`off_field`、`context`；前端据此分成赛场主线、转会市场、场外与赛程、背景脉络。模型漏填时由 Harness 按标题/正文确定性补类。
6. 每个资料层 `LayerLoopSummary` 增加 `checkpoints`。URL 收集、资料精简、增强补采和撰写交付都记录输入、输出、模型轮次、工具轮次、候选数、正文片段数、媒体资产数等可读摘要，并写入最终 Harness Trace。
   Skill runtime 的 `max_tool_rounds` 展示四层流水线合计预算，避免 Trace 出现单层预算与总使用量口径不一致。
7. 模型仍不能输出媒体 URL。所有 `media_assets` 必须由 Harness 注入；模型只描述事件和证据引用。

## 后果

- 首图和事件画面更接近“懂球帝式”的阅读体验，但仍保留版权边界。
- 如果官方频道没有合适视频，报告不会自动塞入不相关高光或新闻图。
- Trace 能看出每层是否真正工作、是否读到正文片段、是否补到媒体资产。
- 报告栏目更少、更厚，适合日报阅读和二次编辑。

## 验证

- 测试覆盖官方视频不能只靠比分/年份匹配。
- 测试覆盖时间线事件可以触发 timeline 视频位。
- 测试覆盖证据里的进球分钟可以被确定性补成 `match_timeline`。
- 测试覆盖四层资料流水线都写入 checkpoints，并能进入 Harness Trace。
