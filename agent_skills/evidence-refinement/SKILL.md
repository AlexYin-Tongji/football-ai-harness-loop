# 资料精简层

## 目标

把 URL 收集层的候选资料压缩为短证据包。精简层只读候选链接的元数据和短摘录，不新增事实、不补背景、不改来源等级。输出必须让撰写层能直接回溯原链接。

## 每条证据摘要格式

每条精简结果都应包含这些信息：

- `source_evidence_id`：原候选证据 ID，必须来自输入。
- `title`：保留原题核心实体和动作，去掉营销式修饰。
- `original_url`：由原候选证据保留给 Harness；精简文本中也要明确“原链接随 evidence_id 保留”。
- `concise_summary`：2-4 句中文摘要，说明该来源实际说了什么。
- `key_points`：最多 5 条，保留时间、金额、比分、分钟、球员、球队、状态词和不确定性。

## 写法

- 用“该来源称/报道/确认/提到/否认”区分来源立场。
- 对 `unverified_lead` 保留“线索/传闻/尚未核实”字样，不把标题升级成事实。
- 对转会事件标出阶段：关注、接触、谈判、报价、原则协议、体检、官宣、辟谣。
- 对比赛事件只保留证据里出现的分钟、比分、进球者和红黄牌；没有就写未知。
- 对球员背景只保留证据或结构化来源提供的字段，不用常识补全。
- 删除重复转载、空泛评价和无新事实的改写。

## 交付边界

- 精简层不调用新工具，不扩展来源。
- 不复制长段原文，不保存完整新闻正文。
- 不输出 Markdown 正文；只输出符合 schema 的 JSON。
- 如果模型不可用，Harness 可以用确定性短摘要兜底，但仍保留 URL 和来源状态。
