# ADR 0019：北京时间窗口与结构化赛程优先

- 状态：Accepted
- 日期：2026-07-05

## 背景

真实生成暴露出日报框架的三个系统性问题：

1. 用户在 7 月 5 日生成 7 月 3 日日报时，RSS、GDELT、NewsAPI 和模型提示仍容易使用运行当天或来源当地日期，导致 7 月 4 日/5 日内容混入。
2. 日报把新闻发现当作比赛事实来源，缺少结构化赛程/赛果兜底，甚至会漏掉当天有哪些世界杯比赛。
3. 媒体增强会消耗上下文和栏目注意力；在核心事实链路不稳定时，图片和视频不应默认参与生成。

## 决策

1. 新增 `ReportTimeScope`。`report_date` 一律解释为北京时间自然日，并显式保存 `window_start_utc`、`window_end_utc`、`data_cutoff_utc` 和可读标签。
2. 资料收集使用半开时间窗：`window_start_utc <= published_at < data_cutoff_utc`。当请求历史日期时，`data_cutoff_utc` 等于该北京时间自然日结束；当天请求则截到当前 UTC 时间。
3. 公共任务在进入研究流水线前就生成 `time_scope`，URL 规划、RSS/API 过滤、结构化赛程和最终合稿共用同一个窗口。
4. 已批准的 football-data.org API 在世界杯日报和足球日报中作为结构化赛程/赛果证据优先注入。结构化证据不会替代新闻来源，但必须进入候选池，并在资料精简后强制保留，防止模型漏掉当天比赛。
5. 比分方向修复扩展到标题、摘要和小节。证据写成 `Paraguay 0-1 France` 时，中文句子若按“法国战胜巴拉圭”叙述，应修为 `法国 1-0 巴拉圭`。
6. 图片/视频媒体管线默认关闭，只能通过 `FOOTPULSE_MEDIA_PIPELINE_ENABLED=true` 显式开启。旧的 `LICENSED_MEDIA_ENABLED` 不再作为默认开关读取。

## 后果

- 日报的“今天/昨日/近期”不再由模型、服务器当天或英美发布时间自行解释。
- football-data 结构化赛程会先回答“这一天到底有哪些比赛”，新闻证据再补充战报、转会和场外上下文。
- 7 月 3 日北京时间日报不会把北京时间 7 月 5 日的法国 1-0 巴拉圭写成当天主线。
- 媒体链路仍保留，但在核心产品质量稳定前不会默认影响研究和写作。
- 没有配置 football-data 时，系统仍只使用批准新闻源，但会在 warnings/trace 中暴露结构化赛程缺口。

## 验证

- 单元测试覆盖北京时间 7 月 3 日对应 UTC `2026-07-02T16:00:00Z` 到 `2026-07-03T16:00:00Z`。
- 单元测试覆盖 Guardian RSS 在该窗口外的条目被过滤。
- 单元测试覆盖 football-data 日报结构化证据只保留北京时间当天比赛。
- 单元测试覆盖法国/巴拉圭比分方向在标题、摘要和小节中修复。
- 产品状态测试覆盖媒体默认关闭。
- 真实生成回归使用 2026-07-03 日报，检查 evidence 与 trace 中是否出现结构化赛程、是否排除 7 月 4 日/5 日证据。
