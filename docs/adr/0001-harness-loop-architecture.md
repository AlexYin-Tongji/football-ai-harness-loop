# ADR-0001：采用受控 Harness 与显式 Loop

- 状态：Accepted
- 日期：2026-06-28

## 背景

新闻整理与比赛预测都需要多步骤执行，但风险不同：前者容易出现来源误归因、重复和事实幻觉；后者容易出现数据泄漏、概率失准与赛制混淆。一个自由运行的通用智能体很难提供稳定的审计与发布边界。

## 决策

采用“确定性工作流控制器 + 受限模型步骤”的 Harness：

- 工作流状态、分支、重试和终止条件由代码定义。
- LLM 仅用于语义抽取、聚类辅助、摘要和解释等非确定性步骤。
- 数值计算、赛程状态、概率归一化和发布权限使用确定性代码。
- 每个模型步骤前后都有 schema、证据、数值和政策校验。
- 内容与预测分别形成闭环，反馈进入评估集后再改变系统。
- 自动修订最多两轮；任何步骤可暂停、重放、降级或转人工。

## 为什么不选其他方案

### 单一长对话智能体

上下文会持续膨胀，失败难以定位，无法可靠地从中间步骤恢复，也难证明某个事实来自何处。

### 一开始就使用多智能体“讨论”

角色数量不会自动带来独立证据，反而增加延迟、成本和一致性问题。只有当离线评估证明某个独立角色（如引用审计）能显著降低错误时才引入。

### 纯 DAG、完全不用模型

跨语言实体解析、同义主张聚类和自然语言成稿仍适合模型。关键是把模型放在有边界、可验证的位置。

## 结果

正面：

- 每条输出可定位到输入、代码、提示词、模型和审批人。
- 失败可局部重试，供应商可替换，发布可硬性隔离。
- 线上反馈能够进入可度量的改进循环。

代价：

- 需要维护状态机、schema、评估样本和运营队列。
- 初期开发量高于“一个提示词直接写文章”。
- 工具接口与领域模型必须保持严格版本化。

## 验证方式

- 建立 100 个主张聚类/引用覆盖的黄金样本。
- 对每次提示词或模型变更运行回归评估。
- 记录事实错误、人工修改量、循环次数、延迟与成本。
- 只有统计上或运营上可观察的改善才进入生产。
