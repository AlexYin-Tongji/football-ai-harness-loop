# ADR 0018：产品级 Trace、Claim 质量门、Agent Eval 与可恢复任务账本

- 状态：Accepted
- 日期：2026-07-04

## 背景

《今日球脉》已经具备 Leader 分栏、小组循环、资料精简和总编辑合稿，但真实体验仍暴露出四类问题：

1. 用户只能看到粗略进度，无法判断哪一层资料不足或降级。
2. 报告通过 section 级引用校验，但带比分、分钟、金额和履历数字的单句事实仍可能缺少逐句证据。
3. 日报需要“相比昨日发生了什么”，而不是每次都像第一次看见这条新闻。
4. 单元测试覆盖函数行为，但缺少完整 Agent 产物级 eval。

## 决策

1. 新增统一阶段注册表。后端、任务事件、能力接口和前端进度使用同一组阶段定义，避免 Skill、runtime、实际 phase 和 UI 文案分裂。
2. `research_jobs` 增加 `research_job_events`。每次任务状态更新都写入可展示事件，包括阶段、进度、可读说明和结构化 payload。完成事件保存 trace step 摘要。
3. `story_memory` 保存已完成报告的 story cluster 摘要。后续同类日报可读取 `previous_story_memory`，用于提示“相比上一版/昨日是否有变化”；记忆不能单独当作事实来源。
4. 质量门增加 claim 级检查：正文会拆成可核验句子，带比分、分钟、金额、年份、进球、出场等数字的 claim 必须能在引用证据中找到同一数字；发现线索相关 claim 必须逐句保留传闻标签。
5. `EditorialColumnPlan` 增加 `coverage_requirements`。Leader 和 fallback 计划都必须给小组交付合同，战报、转会、人物、教练和场外栏目按不同字段检查覆盖缺口。
6. 新增 `services.report_api.evals`。Agent eval 检查完整结果的 trace、引用、传闻标签、栏目覆盖和媒体绑定，作为单元测试之外的产物级回归入口。
7. 本地 Beta 继续使用 SQLite，但角色从“任务结果存储”升级为可恢复 durable ledger：任务、事件、审计、预测结果、故事记忆和 workflow checkpoints 分表保存；服务重启时，`queued/running` 任务会进入 `waiting_for_resume`，应用启动后自动重新入队。若已经写入 `report_request_ready` 检查点，恢复会跳过资料收集层，直接从撰写与质量门继续。生产版可把同一阶段表和事件 payload 映射到 Temporal + PostgreSQL，不改变上层产品合同。
8. 最终总编辑合稿即使到达最后一次尝试，也不能绕过栏目覆盖门。若高思考合稿持续漏掉 Leader 栏目，系统必须改用已完成的分桌草稿生成保守合稿；保守合稿仍要重新检查栏目合同、补确定性时间线和人物卡，并复用同一媒体挂载流程。
9. 资料进入写作层前生成 `numeric_claim_ledger`。它从已登记 evidence 的标题和摘要中抽取可写数字 claim，交给专栏研究、分桌写作和最终总编辑；模型只能选择 ledger 中由对应 `evidence_ids` 支撑的数字，不能凭常识补写 16 强、年份、分钟、比分或金额。
10. 最终总编辑每次合稿尝试都要写入可恢复 trace。`desk_drafts_ready` 保存分桌草稿摘要和检查点；`editor_synthesis_attempt_N` 保存规范化输出、校验错误和小节摘要，便于复盘是哪个小节、哪个证据集合和哪个数字失败。
11. claim 校验失败不再直接让今日球脉任务失败。系统先把具体错误和 claim ledger 反馈给模型做有界修复；若仍未通过，则进入 `claim_repair` 和 deterministic finalizer，清理无证数字、补齐 Leader 栏目，并用证据保守小节交付可编辑稿。详细错误留在 trace，用户可见报告只保留简洁复核提示。
12. 新增证据状态护栏。Leader、fallback 分栏、小组合同和最终质量门必须区分 `completed_match`、`upcoming_fixture`、`off_field` 和 `transfer`。赛前、抵达酒店、开球时间、赛程安排和敌意接待证据不得进入 `match_report`，也不得写成“今日赛场/最终/击败/展开较量”等已完赛口径。
13. 正文质量门拒绝空洞占位写作。战报正文不能用“关键事件尚待确认、暂未明朗、比赛进程存疑、待补充”等句式填充篇幅；缺口只能放入 warnings、unknowns 或 trace，正文必须只交付证据支持的内容。
14. 比分和开球时间分开处理。`18:00`、`01:00` 等时间不能被当作比分或已完赛信号；战报状态需要已完赛语义或真实比分/赛果证据共同支撑。
15. 媒体交付从“人物卡附带图片”扩展为“栏目级图片目标”。最终媒体层会从二级标题和正文抽取人物或球场候选，并继续只走 Source Registry 已批准的 Wikimedia Commons 许可过滤；官方高光只在真实 match section 中查询，避免用整篇标题误匹配历史经典视频。
16. 今日球脉不再以节省模型输出 token 为主要约束。Seed 精简、Leader 分栏、专栏研究、分桌写作和总编辑合稿的输出上限必须足以返回完整 JSON；DeepSeek 返回 HTTP 200 但 JSON 非法时，Provider 先执行一次格式重试并临时提高该次输出上限，再决定是否降级。
17. Leader 的初始职责收缩为轻量分派。初始 Seed 只给 Leader 做大致栏目判断；每个栏目小组才是主要执行者，负责本栏目范围内的资料收集、精简、增强和分稿。小组循环采用有界自适应迭代，默认多轮但硬上限低于无限探索，避免因盲目扩搜污染上下文。
18. Deterministic finalizer 必须遵守与总编辑相同的证据状态门。混合 match_report 栏目进入兜底时，先筛出已完赛证据生成战报；赛前、酒店、开球时间和氛围材料只能降级为场外或背景小节。若分桌草稿和证据保守小节都未通过校验，系统降级为最小证据摘要，并把每一层失败原因写入 progress payload。
19. 栏目覆盖验收必须同时检查 `evidence_ids` 与最终 `section.category`。context 小节不能冒充转会栏目，off_field 小节不能冒充战报栏目；分桌与 deterministic finalizer 的 trace payload 必须输出 category 分布，便于定位“为什么只剩一栏”。
20. `transfer` 小节必须引用真正转会证据，不能用“无转会新闻”或赞助/规则材料凑栏目。比分修复需要按正文队名顺序重写比分方向，避免“法国以0-1战胜巴拉圭”这类中文读法错误。自动媒体挂载必须二次过滤 evidence 绑定与目标标题，空 evidence 封面视频和明显错配的人物/场馆图不得进入最终报告。

## 后果

- 用户和开发者可以看到每层交付，而不只看到最终报告。
- 今日球脉的稳定性从“提示词尽量完整”转为“Leader 合同 + 小组缺口 + 合稿覆盖门 + claim gate + eval”共同约束。
- 赛事事件和图片不再只靠最终模型自由发挥；增强层和媒体层会围绕 evidence 生成目标并按位置绑定。
- 战报证据中已有比分、分钟、红黄牌或 VAR 细节时，战报栏目必须在正文或时间线中保留这些关键事件；否则进入修复或保守合稿，而不是交付泛泛总结。
- 数字事实从“提示词要求模型自律”改为“证据账本 + 小节引用 + 有界修复 + 保守交付”共同约束；质量门仍严格，但失败会转为可追踪的降级交付。
- “框架太保守”的问题不能通过盲目增加循环次数解决。系统应该先修正状态分类和验收合同：没有已完赛证据就不写战报，没有图片就形成许可图片目标或复核提示，正文不能用未知占位句冒充完成。
- 赛前材料仍可写，但必须成为赛程、场外或备战栏目；它可以解释观赛安排和球队环境，不能冒充当天已经发生的比赛。
- 图片来源仍保持合规边界：不新增生产抓取源，不抓取未批准图床；找不到许可图片时保留人工补图目标，而不是自动使用不可授权图片。
- 输出 token 预算不是主要优化目标；优先保证完整 JSON、可读分稿和可追踪中间产物。成本控制通过来源白名单、轮次上限、超时和人工回退实现，而不是把关键写作阶段压到过小输出上限。
- 小组的意义在于“栏目内自治”：它们不只是接收 Leader 处理好的材料，而要在 Leader 给出的栏目边界内继续收集、精简、增强并产出分稿。
- `previous_story_memory` 可能提示昨日对比，但任何事实仍必须由当前 evidence 支撑。
- 本地恢复支持从 `report_request_ready` 检查点继续，避免重复资料收集；更细粒度的活动级恢复仍需要 Temporal worker、PostgreSQL 锁、活动幂等键和外部 API 幂等策略。
- 兜底交付不再绕过“赛前不是战报”的规则；这会牺牲一部分标题完整性，但能避免为了交付而把未开赛材料写成假赛果。
- 如果当天没有已完赛战报或真实转会证据，产品可以只展示场外/背景栏目，但不能生成空的“赛场战报”或伪转会栏目来凑版式。
- 自动媒体宁可少挂，也不能挂明显不相干的封面或人物/场馆图；被过滤的媒体可以通过 trace 和人工补图目标继续复核。

## 验证

- 任务事件接口返回完整阶段事件。
- 服务重启后未完成任务进入恢复队列，并在应用启动时自动执行。
- 存在 `report_request_ready` 检查点时，恢复路径不得重新调用资料收集层。
- 阶段表接口返回今日球脉统一阶段。
- claim gate 能拒绝引用证据中不存在的比分。
- numeric claim ledger 会进入今日球脉最终合稿输入，且输入压缩时仍保留最重要的 ledger 摘要。
- 今日球脉最终合稿因无证数字连续失败时，不返回失败任务；系统进入 claim repair / 保守合稿并产出通过质量门的报告。
- `desk_drafts_ready` 和每次 `editor_synthesis_attempt_N` 能被保存为事件 payload 或 workflow checkpoint，用于定位失败产物。
- eval 能识别缺失 trace、传闻标签或媒体绑定。
- eval 能识别证据中存在分钟级比赛事件、但最终 `match_timeline` 没有覆盖该 evidence 的日报。
- 最终合稿持续漏栏目时，服务会回退到 deterministic daily finalizer，且该保守稿仍必须覆盖缺失栏目。
- 质量门能拒绝把 England-Mexico 赛前/抵达/开球证据写成今日已完赛战报。
- 质量门能拒绝 placeholder-heavy 战报正文。
- fallback Leader 会把 upcoming fixture 证据分配到场外或背景，而不是战报。
- 媒体层能在没有人物卡时，从栏目正文抽取人物名并挂载 Wikimedia Commons 图片。
- DeepSeek `invalid_response` 会被记录为结构化降级原因，并先触发 JSON 格式重试。
- 今日球脉最终合稿和 stable 合稿的输出上限提高到配置上限范围，测试断言不再限制在 2000-3000 token。
- 初始 Leader seed 控制在轻量范围，栏目小组承担后续收集、精简和增强。
- mixed match_report 栏目包含赛前材料和完赛材料时，deterministic daily finalizer 只把完赛证据保留为 match section，并在分桌稿失败时记录 `desk_sections_validation_failed`。
- 无完赛战报、无转会证据但有赛前/赞助/规则/文化材料时，deterministic daily finalizer 保留 `off_field` 与 `context` 两类栏目，并在事件 payload 写出 `category_counts`。
- 质量门能拒绝无转会证据的 `transfer` 小节；比分修复能按中文队名顺序调整 0-1/1-0；媒体过滤能移除空 evidence 封面视频和目标名不匹配的 Commons 图片。
- 全量测试和静态检查通过。
