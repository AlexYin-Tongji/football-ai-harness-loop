# DeepSeek 比赛预测报告设计

## 1. 定位

MVP 不训练自有大模型，也不建设重型 ML 平台。Harness 将截至某个时间点的结构化比赛资料交给 `deepseek-v4-pro`，要求其返回可验证 JSON，再生成一份供用户整理和发布的预测报告。

当前输出由两层组成：可复现的 **Poisson / Elo+Poisson 统计基线**，以及 DeepSeek Pro 基于伤停、阵容、战术和来源冲突形成的 **AI judgment**。产品分别展示两者，不得使用“必然”“稳胆”等确定性文案。

## 2. 报告回答的问题

1. 90 分钟胜/平/负倾向与三项概率。
2. 可能比分区间。
3. 淘汰赛晋级倾向；明确区分常规时间、加时和点球。
4. 支持该预测的因素。
5. 可能使预测失效的反方证据与未知项。
6. 用户适合关注的战术或人员看点。

## 3. 上下文包

大模型不能凭自身知识回答正在进行的世界杯。每次调用只使用 Harness 生成的时间点快照：

```json
{
  "match": {
    "teams": ["A", "B"],
    "kickoff_utc": "2026-06-28T19:00:00Z",
    "stage": "round_of_32",
    "venue": "..."
  },
  "cutoff_at": "2026-06-28T10:00:00Z",
  "team_strength": [],
  "recent_matches": [],
  "availability": [],
  "tactical_notes": [],
  "sources": [],
  "missing_fields": []
}
```

所有事实带来源 ID 和时间。赛后才出现的信息不得进入赛前快照；官方首发版本与 T-24h 版本分别保存。

## 4. 模型分工

- `deepseek-v4-flash`：长资料抽取、翻译、实体归一、重复信息压缩。
- `deepseek-v4-pro`：综合比赛上下文，生成最终结构化预测和报告提纲。
- 默认不并行调用多个 Pro；只有校验失败或高冲突比赛才触发一次受限复核。
- Provider 层允许以后切换模型或对少量样本做 A/B 评估。

## 5. 结构化输出

```json
{
  "home_win": 0.42,
  "draw": 0.31,
  "away_win": 0.27,
  "qualification": {"home": 0.58, "away": 0.42},
  "scorelines": ["1-0", "1-1", "2-1"],
  "supporting_factors": [
    {"claim": "...", "evidence_ids": ["ev_1"]}
  ],
  "counter_factors": [
    {"claim": "...", "evidence_ids": ["ev_2"]}
  ],
  "unknowns": ["首发尚未公布"],
  "confidence": "low|medium|high",
  "summary": "..."
}
```

## 6. 确定性校验

Harness 在接受输出前检查：

- JSON schema 完整，所有概率位于 `[0, 1]`。
- 90 分钟三项概率之和为 1（允许极小舍入误差）。
- 淘汰赛晋级概率之和为 1；小组赛不得返回晋级字段。
- 每个关键事实因素至少关联一个上下文中的证据 ID。
- 报告未引用 cutoff 之后的信息。
- 模型没有把缺失字段写成确定事实。
- 文案明确区分事实、来源观点和 AI 推断。

首次失败允许用错误清单复核一次；再次失败则返回资料包和警告，不无限循环。

## 7. 生成节奏

- T-24h：常规赛前报告。
- T-6h：更新球队消息和伤停。
- T-75min：官方首发可用时生成最终版。
- 开赛后：冻结赛前版本；MVP 不做实时胜率。

每次版本包含 `context_snapshot_id`、`provider`、`model`、`prompt_version`、`generated_at` 和 token 使用量。

## 8. 评估而非训练

赛后回填真实结果，持续计算：

- Brier Score：衡量概率误差。
- Log Loss：识别过度自信的错误。
- 方向准确率：仅作易懂的辅助指标。
- 输出稳定性：同一上下文重复调用的概率偏差。
- 引用覆盖率与用户修改率。

首 30 场只展示样本和观察值，不宣称“已校准”。达到足够样本后，按比赛阶段、强弱差和数据完整度分组检查。

## 9. 轻量模型的当前实现

每队至少有三场来自批准结构化来源的近期赛果时，Harness 计算 Poisson 基线；存在有来源的 Elo 时再调整双方期望进球。样本不足时返回“基线不可用”，禁止使用内置球队强弱或模型记忆补齐。

统计基线在模型输出通过 schema 和引用校验后由代码注入，因此模型无法改写其数值。赛后由 `result_writer` 回填赛果并累计 Brier Score 与 Log Loss。

继续评估以下退出信号：

- DeepSeek 概率的 Brier Score 连续显著差于简单基线。
- 同一上下文重复输出不稳定。
- Pro 成本或延迟超过产品预算。
- 用户更需要可复现的概率，而不是综合研判。

即使增加基线，也不需要训练大模型；DeepSeek 继续负责证据综合和报告表达。

## 10. 用户可见模板

```text
AI 比赛研判（不是确定赛果）

截至 2026-06-28 18:00（北京时间），DeepSeek V4-Pro 判断：
90 分钟 A 胜 42%、平 31%、B 胜 27%；最可能比分区间为 1-0、1-1、2-1。

支持因素：……（来源 1、2）
反方证据：……（来源 3）
未知项：官方首发尚未公布。

模型与提示词：deepseek-v4-pro / match-report-v1
```

用户可以复制或导出报告，自行整理后发布；产品不自动连接社媒。
